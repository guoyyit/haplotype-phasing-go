# 输入/输出文件格式

所有文件均为 UTF-8、制表符分隔（TSV）。空行与以 `#` 开头的行会被忽略；
单独成行的 `#variants` / `#genotypes` / `#reads` / `#trios` 是段标记，
可用于自描述。列标题行使用下划线形式的标识（如 `variant_id`、`sample_id`、
`read_id`、`child_id`），会被自动识别并跳过。

位点按文件中的顺序赋予 0 基下标，分相、块与输出均按该顺序。

## 1. 位点文件（`-variants`）

每行：`variant_id chrom pos ref alt`

| 列 | 含义 |
|---|---|
| variant_id | 全局唯一位点 ID |
| chrom | 染色体 |
| pos | 非负整数坐标 |
| ref | 参考等位基因（规范 A0） |
| alt | 备选等位基因（规范 A1） |

仅支持二等位基因位点。示例见 `examples/variants.tsv`。

## 2. 基因型文件（`-genotypes`）

每行：`sample variant_id gt`

- 样本按首次出现顺序记录，输出沿用该顺序。
- `gt` 为未分相基因型，分隔符 `/` 或 `|` 等价（输入的相位不被采信）。
- 缺失与部分缺失：
  - `./.`：两条等位基因均缺失（倍性 0）。
  - `A/.` 与 `./A`：仅观测到一条等位基因（倍性 1）。缺失记号 `.` 出现
    在两个等位基因位置的任意一侧都按部分缺失处理，实际观测到的那一条
    等位基因被保留；输入使用 `/` 或 `|` 分隔时行为相同。
  - `A/A`：纯合；`A/G`：杂合。
- 等位基因合法性：基因型中出现的等位基因必须等于该位点的 `ref` 或
  `alt`。出现第三等位基因（如 `A/X`、`./X`、`X/A`）属于明确的输入错误，
  服务以可定位的文件:行号错误拒绝本次运行，不会静默改写，也不会把该记号
  当作第三等位基因写入输出。（读段文件中的非 ref/alt 观测仍按既有约定
  忽略、计数并打印 `notice`，见下文第 3 节。）
- 未出现在文件中的“样本×位点”组合按完全缺失处理，不会导致失败。

规范等位基因顺序：杂合位点的两个不同等位基因以 `ref` 为 `A0`、`alt` 为
`A1`。输出中的 `h1`/`h2` 用 `A0`/`A1` 表示该单倍型携带哪个规范等位基因。

## 3. 读段文件（`-reads`，可选）

每行：`read_id sample variant_id allele`

- 相同 `(read_id, sample)` 的多行按位点顺序聚合成一条读段。
- `allele` 必须等于该位点的 `ref` 或 `alt`；`.` 为空观测。
- 无效观测（未知位点、缺失/非 ref-alt 等位基因）被忽略，打印 `notice`
  并计入冲突/告警，不会静默丢弃或中止。
- 同一条读段在同一位点出现多个矛盾等位基因时，按等位基因字典序取最小者，
  该“读段内部冲突”会作为 notice 与冲突计数上报。

## 4. 家系文件（`-trios`，可选）

每行：`child father mother`

每个 child 至多一行。父、母、子必须是基因型文件中的样本 ID；缺失样本不
产生遗传约束（视为信息不足），不报错。

## 5. 分相输出文件（`-out`，格式版本 `1.1`）

当前写出格式版本为 `1.1`（文件首行 `#haplophased  1.1`）。版本说明与
既有版本回读兼容结论见本节末尾“格式版本与兼容性”。

段按固定顺序排列，便于机读与重读：

```
#haplophased  1.0
#variants        位点定义（同输入）
#trios           家系定义（同输入）
#reads           全部有效读段观测（保证可复现读段证据）
#config          单行紧凑 JSON，即本次运行使用的完整配置
#phase           每样本每位点一行的分相结果
#blocks          每样本每个分相块一行
#stats           运行级统计键值
```

`#phase` 列：

| 列 | 含义 |
|---|---|
| sample | 样本 ID |
| variant_index | 0 基位点下标 |
| variant_id | 位点 ID |
| status | `PHASED` / `UNPHASED` / `HOMOZYGOUS` / `PARTIAL` / `MISSING` |
| low_cov | `1`=覆盖度低于 `min_site_depth` |
| a0, a1 | 规范等位基因（ref/alt） |
| h1, h2 | 两条单倍型的等位基因：`A0`、`A1` 或 `.`（未分相/缺失） |
| violation | `1`=违反家系孟德尔遗传约束 |

列不变量（对任意一行恒成立）：

- `a0`、`a1` 始终等于位点文件中该位点的 `ref`、`alt`，缺失记号永远不会
  出现在这两列；
- `h1`、`h2` 只取 `A0`、`A1` 或 `.`，其中 `.` 仅表示未分相或缺失，绝不
  表示某个具体观测等位基因；
- 只要基因型包含缺失记号，状态就不可能是 `PHASED`。

status 语义：

- `PHASED`：杂合位点且已分相，`h1`/`h2` 为两个不同等位基因。
- `UNPHASED`：杂合位点但未分相，或违反家系约束（同时 `violation=1`），
  不计入正确分相。
- `HOMOZYGOUS`：纯合位点，两条单倍型相同。
- `PARTIAL`：仅观测到一条等位基因（部分缺失，无论缺失记号原本在左还是
  在右），有观测的单倍型给 `A0`/`A1`，另一条为 `.`。
- `MISSING`：完全缺失基因型。

违规位点的输出与回读语义：

- 违规的**杂合**位点在 1.1 中写为 `status=UNPHASED`、`violation=1`，
  `h1=A0`、`h2=A1` 按规范的无序形式记录实际观测到的两个等位基因；该位点
  仍不计入已分相杂合位点数。
- 违规的**纯合**位点写为 `status=UNPHASED`、`violation=1`，`h1` 与 `h2`
  为相同的规范等位基因调用（`A0/A0` 或 `A1/A1`）。
- 两种违规行都携带重新推导违规所需的完整基因型，因此一次运行生成的文件
  被重新读入并再次分相时，违规标记、`PHASED`/`UNPHASED` 状态以及全部统计
  计数保持不变。

`#blocks` 列：`sample block_id start_idx end_idx site_count hets_count
support conflict confidence error_rate status`。

- `block_id` 形如 `BLK-<sample>-0001`，按样本与位置确定性编号。
- `start_idx`/`end_idx` 为位点下标闭区间。
- `support`/`conflict` 为块内已裁决边的多数/少数票合计。
- `confidence` 与 `error_rate` 均四舍五入到 4 位小数且和为 1。
- status：`OK`、`LOW_CONF`（置信度低于 `min_block_confidence`，仍输出）、
  `SINGLETON`（单个杂合位点，无相邻证据，置信度记 1）。

`#stats` 的键与 `model.RunStats` 一一对应，含义见
[algorithm.md](algorithm.md) 的“统计字段”。

### 格式版本与兼容性

| 版本 | 说明 |
|---|---|
| `1.1` | 当前版本。违规杂合位点显式记录观测到的两个规范等位基因；部分缺失两侧对称；`a0`/`a1` 恒为 ref/alt；修复了 `#stats` 首行被误跳过的解析问题。新写出的文件均为 1.1，可逐字节回读校验。 |
| `1.0` | 首个发布版本，仍可被当前服务读入。对 1.0 文件执行 `-reread` 时按 1.0 规则重新写出：违规杂合行保留其历史的 `.`/`.` 编码，违规纯合行与其它行也保持与原文件逐字节一致，因此既有结果文件的回读校验继续通过。 |

1.0 已知缺陷的兼容性结论：1.0 版本在解析“缺失记号位于左侧的部分缺失
基因型”（如 `./T`）时会将其误当作二倍体杂合处理，对应输出行本身记录的
就是当时的错误结果（`a0` 为 `.`、状态为 `UNPHASED` 等）。当前服务读入
1.0 文件时严格按其字面内容重建并按 1.0 规则重新写出，因此**包括这类历史
缺陷行在内的 1.0 文件 `-reread` 仍逐字节通过校验**；缺陷行被原样保留并可
按行定位，不会被“悄悄修正”或删除。若对相同原始输入重新运行（生成 1.1
文件），则会得到正确的 `PARTIAL` 行。任何真正的不一致都会在首个差异行
报告 1 基行号与两侧行内容。未知格式版本在读入时被明确拒绝。

## 6. 报告文件（`-report`）

人读纯文本：总体计数与每样本的块、置信度、违规摘要。该文件仅供阅读，
不参与重读；机读与往返校验以 `-out` 文件为准。
